## 🏆 What 0.3.1 is

A network twice as wide, trained on 70% more data, and a faster engine to carry it. Unlike 0.3.0, whose gain over 0.2 appeared only head to head, **0.3.1's gain shows up against other engines too**:

| test | games | result |
|---|---|---|
| **machete 0.3.1** vs machete 0.3.0, 10+0.1 | 596 | 137 W · 371 D · 88 L · **+33 ± 30** (SPRT accepted) |
| vs Spike 1.4, 2+1, the same openings as 0.3.0 played | 60 | **49 W · 9 D · 2 L** (0.3.0: 36 · 19 · 5) |
| vs Rybka 2.3.2a, 2+1, same openings | 60 | **43 W · 11 D · 6 L** (0.3.0: 40 · 16 · 4) |
| vs Koivisto 9.0, 2+1, same openings | 60 | **1 W · 15 D · 44 L** (0.3.0: 0 · 8 · 52) - machete's first win against Koivisto |

Against those three engines together 0.3.1 scores **61.4%** where 0.3.0 scored **54.2%** on the same openings, roughly +50 Elo outside machete's own family, with an uncertainty of about the same size. On the CCRL Blitz scale that puts 0.3.1 somewhere around **3050-3150**, one CPU; `ASSESSMENT.md` explains why the anchors only support a range.

## ✨ What changed

- **Network C20: 512 hidden units, twice 0.3's**, with the same king buckets (8 × 768 inputs → 512 → 8 output layers, int16, format 3). Trained on **262 million** positions, 70% more than C7: C7's data plus 10 million positions the engine's own games reach, labelled by Stockfish on two Raspberry Pis, and 98 million more from the theoden8 corpus (Stockfish 16 at depth 18-22). The width alone is worth **+29 ± 28** at equal time against a 256-wide network trained on the same data, after paying for the slower evaluation.
- **AVX2.** The network's accumulator updates run on 256-bit registers when the CPU has AVX2, chosen at start-up, so one binary still runs everywhere; the engine's first info line says which. Mach cannot express AVX2 yet, so these kernels are machine code generated by `harness/nnuegen.py` and tested against the portable loops. **+4.3%** nodes per second on a Zen+ CPU, which splits 256-bit work in two; newer CPUs should gain more.
- **A faster move picker**, **+3.9%** nodes per second: the selection loop keeps its bounds in registers, which Mach 6.5 does not do for it (reported as briar-systems/mach#4162).
- **Built with Mach 6.5.0 and mach-std 9.2.0.** No speed change of its own.
- **The search is 0.3's**, unchanged: the node-count signature is the same 154,591.
- **binpack is back** in the release downloads for every platform; 0.3.0's release had dropped it.

## 📦 What's in the box

The **`-complete.zip`** is the one to play with:

| file | what it is |
|---|---|
| `machete.exe` | the engine: one static binary, no installer, no runtime |
| `machete.nnue` | its network (8 × 768 → 512 → 8 output layers, int16, format 3; 6.3 MB) |
| `README.txt` | setup, options, strength notes |
| `SHA256SUMS.txt` | checksums for the two files above |

The other archives are what CI builds for every platform - `machete` and `binpack` for Windows (x86-64), Linux (x86-64 and aarch64) and macOS (x86-64 and Apple silicon) - executables only; the engine needs **`machete.nnue`** (attached separately) beside it. Only the Windows build has been played and gated. **A 0.3.0 network will not load in 0.3.1**: the width differs, and the engine refuses a file of another width.

<details>
<summary><b>🧪 How it was tested</b></summary>

35 gates in `check.sh`, each made to fail on purpose once, among them: exact perft; every mate in one, two and three; a node-count signature; the network's integer arithmetic against a numpy reference, on random and worst-case networks generated at the engine's own width; the incremental accumulator against a fresh one after every move of random games. The AVX2 kernels are held to the SSE2 ones on random data (a deliberately broken kernel was caught). Every speed change left the search tree identical; the network's strength was judged by SPRT at a real clock and then against three outside engines on the same openings as 0.3.0.

</details>
